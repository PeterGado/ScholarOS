**A real gap found by exercising the app over actual HTTP (not just TestClient):** the application had no schema-bootstrap step — every prior stage's tests called `init_db()` explicitly in fixtures, which masked that a genuinely fresh `uvicorn` boot would fail with `no such table: users` on the first request. Fixed by wiring `init_db()` into a FastAPI `lifespan` handler in `main.py` (idempotent, safe on every startup) and, in the process, fixing a latent bug in `init_db()`'s signature: its `target_engine` parameter defaulted to the module's `engine` object bound at *import time*, which is invisible to test-time monkeypatching - changed it to resolve the default at call time so a bare `init_db()` (as the lifespan calls it) honors a patched engine. This let the e2e test fixtures switch from `dependency_overrides` on `get_db` to monkeypatching `app.database.session.engine`/`SessionLocal` directly, so the lifespan-triggered `init_db()` targets the isolated per-test database too, not the real one.
