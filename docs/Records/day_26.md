# Day 26

The product question I keep coming back to is not:

“Can it generate?”

It’s:

“Does it help someone work better with the material they already have?”

ScholarOS uses a provider gateway for both text generation and embeddings. The current Google Gemini integration implements those shared interfaces, while usage checks and metering sit around provider calls.

That separation is useful engineering, but it’s not the measure of product success. A generated answer can look impressive, yet if it isn’t grounded in the person’s material—or doesn’t help them decide what to do next—it may not improve the work.

The harder, more practical test is whether the system helps people find, understand, and use their information while keeping their judgment at the center. Does it reduce the effort of getting back into a project? Does it preserve the source behind an idea?

What would make a tool meaningfully improve the way you work—not just give you something new to try?
