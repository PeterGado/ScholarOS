# Day 5

ScholarOS has moved beyond the idea stage.

The production stack is real: a FastAPI backend with Pydantic schemas, a React and TypeScript frontend, and a PostgreSQL database hosted on Neon. The backend is organized as a modular monolith, so document handling, knowledge retrieval, and writing workflows have clear boundaries without the operational overhead of microservices.

The application is deployed on Fly.io, with the frontend on Vercel. That’s not a claim that the product is finished; it’s the foundation I’m using to build and test the actual workflow.

The real test isn’t whether the stack sounds impressive. It’s whether the product helps someone move from source material to useful thinking and writing with less friction.

If research, writing, or large amounts of information are part of your work, what’s one step you’d want a tool like this to make easier? I’d value specific examples from your day-to-day workflow.
