**Stage 6 — Async Generation: Complete (reviewed 2026-09-15, one real defect fixed).** Wired Stage 5 into the existing Work Item/executor (`app/workers/executor.py`, `app/workers/payloads.py`) — no second queue or worker mechanism. `EnqueueDraftGenerationUseCase` resolves Draft → Agent → User ownership server-side before enqueuing; the executor dispatches a Work Item to either the document pipeline or `GenerateDraftVersionUseCase` based on its `payload_reference` prefix, using the existing bounded retry policy. **Stages 4-6 were originally implemented in a separate workspace session** (commits `ad1842c`, `2c8c81f`, `4532830` — the last explicitly titled "stage 6 complete, needing tests and review"); reviewed here before proceeding to Stage 7 and two real defects were found and fixed: (1) the enqueue path serialized the *entire* `ContextAssemblyInput` directly into `payload_reference` and rejected anything over 512 characters — unusable for any realistically evidence-sized request (Context Assembly's own default budget is 12,000 characters across up to 10 evidence chunks), masked because every existing test used a single trivial one-line evidence string; fixed by writing the context to the existing `ContentStore` and embedding only a short reference in `payload_reference`, exactly mirroring the already-established `ResearchDocument.content_reference` pattern (no schema change, no new persistence category). **Project Writing Stage 8 (Full Validation) is complete — all eight Project Writing stages are now done and the backend is validated end to end.** Nothing committed to git. Full regression suite: 509/509 passing, unchanged since Stage 7.
